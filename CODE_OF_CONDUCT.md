# Code of Conduct

## The standard

Be accurate. Assume the other person is competent and acting in good faith, and
disagree with the argument, not the person.

Two things matter more here than in most projects, because this is a reference
corpus and its whole value is being trustworthy:

**Do not invent facts.** An API name, a version, a URL, a benchmark number — if
you are not sure, say you are not sure. A confident wrong answer in a reference
document costs someone an afternoon. Mark the uncertainty instead:

```markdown
> [!NOTE]
> Unverified — check the tool's current documentation.
```

**Correct the record.** If you find an error in an article, fix it, and say in
the commit message what was wrong and what you checked. Do not quietly improve
wording and leave the error in place. Errors that are found and fixed are worth
more than articles that were never wrong in public.

## Unacceptable

Harassment, personal attacks, or sustained disruption. Publishing someone's
private information. Discriminatory or demeaning comments. Sexualised language.
Deliberately false or misleading technical claims about other people's work.

## Scope

Applies in issues, pull requests, discussions, and anywhere someone is
representing this project.

## Enforcement

Report privately to the repository owner. Reports are handled confidentially.

Responses, in escalating order: a private correction; a public warning; a
temporary ban; a permanent ban.

Maintainers are expected to model this. A maintainer who argues by calling an
contribution naive has done something worse than the contribution.
