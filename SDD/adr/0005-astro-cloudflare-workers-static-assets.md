# ADR 0005 — Astro static output на Cloudflare Workers (не Pages)

- **Статус:** принято
- **Дата:** 2026-10-01

## Контекст
Требование: сайт на Astro, размещаемый на Cloudflare, с полной SEO-оптимизацией
и оптимизацией под языковые модели. Обязательное условие — чтобы поисковики и
агенты читали контент без выполнения JavaScript.

## Решение
Astro 7 в режиме `output: 'static'`, раздача через **Cloudflare Workers со
статическими ассетами** (`wrangler.jsonc` → `assets.directory`). Контент
пререндерится в HTML на этапе сборки. Поиск — Pagefind (индекс на сборке).

## Последствия

**Почему Workers, а не Pages**
- Cloudflare помечает Pages как legacy: «Workers supports most Pages use cases…
  Start new projects with Workers».
- `@astrojs/cloudflare` начиная с v13 **вообще не поддерживает Pages** —
  поддержка удалена, предлагается миграция на Workers.
- Для статики адаптер не нужен вовсе: `dist/` просто загружается как ассеты.
- Pages автоматически игнорировал `node_modules`/`.git`; на Workers это делает
  `.assetsignore` (создан).

**Почему static, а не SSR/on-demand**
- Контент не меняется между сборками → предрендер быстрее и дешевле.
- Краулер получает HTML с первого ответа: для AI-агентов это критично, многие
  не выполняют JS.
- Нет рантайма: нет Cold Start, нет среды исполнения, нет секретов.
- `output: 'static'` = нет зависимости от версии адаптера при обновлениях Astro.

**Цена**
- Нет серверного поиска: полнотекстовый поиск по всем полям и произвольные
  фильтры остались в локальном Python-API (`:8099`), публично недоступны.
- Каждая правка контента = пересборка и деплой (≈90 с). Для базы знаний с
 批次-редактированием это приемлемо; для часто меняющегося сайта — нет.
- Домен фиксируется на момент сборки (`PUBLIC_SITE_URL`); смена домена требует
  пересборки, иначе canonical разъедется.

**Конфигурация, проверенная на живом `wrangler dev`**
- `html_handling: "drop-trailing-slash"` — Astro собирает `foo.html`, канонический
  URL без слеша. По умолчанию `/foo/` отдавал бы 307, и Cloudflare прямо
  предупреждает, что расхождение по слешу создаёт дубликаты для поисковиков.
- `not_found_handling: "404-page"` — Workers, в отличие от Pages, не находит
  `404.html` сам.
- `.md`-файлы отдаются как `text/markdown` (подтверждено замером) — `llms.txt` v2
  рекомендует именно такой формат.

**Что не выбрано**
- Cloudflare Pages: устарел, адаптер его больше не поддерживает.
- Astro + адаптер Workers (SSR): быстрее итерации контента, но требует
  рантайма, Cold Start и не даёт выигрыша для неизменяемого контента.
- Один большой SPA со клиентским рендером: недоступен без JS — провал по SEO.
