# ADR 0006: версия Blender, на которую нацелен корпус

**Статус:** предложено (ожидает решения владельца)
**Дата:** 2026-10-02

## Контекст

Корпус писался против Blender 4.x: в статьях указано `Blender | 4.x |` в таблице
требований, а в коде используются имена, существовавшие в 4.x.

Установлен **Blender 5.2.1 LTS** (`C:\Program Files\Blender Foundation\Blender 5.2`).
Проверка `WIKI/scripts/api_compat.py` прогоняет 316 путей `bpy.*` из всех
python-блоков корпуса через интроспекцию живой 5.2.1 и находит **9 путей,
работавших в 4.x и отсутствующих в 5.2**:

| путь | в 4.x | в 5.2 |
|---|---|---|
| `bpy.ops.export_mesh.stl` | есть | `bpy.ops.wm.stl_export` |
| `bpy.ops.import_mesh.stl` | есть | `bpy.ops.wm.stl_import` |
| `bpy.ops.export_mesh` / `import_mesh` | есть | пространство имён исчезло в 4.0 |
| `Mesh.use_auto_smooth` | есть | удалён в 4.1 → `bpy.ops.object.shade_auto_smooth` |
| `tool_settings.sculpt.detail_type` | есть | `detail_type_method` |
| `tool_settings.sculpt.constant_detail` | есть | `constant_detail_resolution` |
| `tool_settings.sculpt.dyntopo` | есть | свойства нет, переключатель в UI |
| `tool_settings.use_snap_project` | есть | свойства нет |

Отдельно, вне этого списка: `action.fcurves` удалён слотированными Action в 5.x
(12 статей), `scene.sequence_editor.sequences` → `.strips` (2 статьи),
`bpy.ops.xr.*` не существует вовсе (1 статья), движок теперь `BLENDER_EEVEE`,
а не `BLENDER_EEVEE_NEXT` (7 статей). Итого **29 файлов из 173** содержат
хотя бы одно имя, которого нет в установленной версии.

Оговорка о границах измерения: проверка разрешает только пути, корнем которых
является `bpy`. Доступ вида `Action.fcurves` или `Material.use_nodes` требует
списка всех классов RNA, а поддерживаемый вручную список типов сам станет
источником тихих расхождений. Такие обращения (например, старые имена сокетов
Principled BSDF) проверкой не охвачены.

## Решение (требует выбора владельца)

Вариант A — **цель 5.x**. Обновить 29 файлов, указать `Blender | 5.x |` в
таблицах требований, и добавить проверку в конвейер как жёсткий гейт.
Корпус начинает соответствовать тому, что у читателя, скорее всего, стоит.
Стоимость: 29 файлов и пересмотр всех упоминаний версий.

Вариант B — **цель 4.x, зафиксировать честно**. Оставить код как есть, добавить
на сайт страницу «версии API», где перечислены эти 9 расхождений, и в
затронутых статьях дать ссылку на неё. Стоимость: один новый документ плюс
правки в 29 файлах в виде одной ссылки. Корпус продолжает быть верным для
аудитории 4.x и перестаёт вводить в заблуждение.

Вариант C — **версия-развилка, проверка в кодовом блоке**. Оставить 4.x как
основной текст, а в каждом затронутом блоке дать вариант для 5.x. Дороже всего
в поддержке и хуже всего читается.

Нейтрально к выбору: проверка совместимости уже написана и измеряет состояние
корпуса одной командой, поэтому любой из вариантов проверяем после каждой
правки, а не по памяти.

## Проверка

```
& "C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" `
  -b --factory-startup --python WIKI/scripts/api_compat.py
```

Ненулевой код возврата при пути, которого нет ни в одной версии. Путь,
переименованный между версиями, не считается ошибкой: он попадает в
`KNOWN_RENAMED` и требует решения, а не молчаливого исправления.
