# CONTRIBUTING — как писать в базу

Короткие правила, которые экономят больше всего времени. Архитектура: `../SDD/ARCHITECTURE.md`.

## Окружение
Python 3.11+; единственная внешняя зависимость — `PyYAML` (`pip install pyyaml`).
Всё остальное — стандартная библиотека.

## Добавить статью (3 шага)

1. **Возьми шаблон** из `WIKI/templates/`: `prompt.md`, `setup.md`, `workflow.md`, `case.md`.
   Шаблон — это контракт структуры, а не украшение: по нему потом пишутся проверки.
2. **Создай файл** в правильной папке с правильным именем:
   - промпт → `WIKI/prompts/NN_slug.md` (номер = порядок в `INDEX.md`),
   - сетап → `WIKI/setups/setup_NN_slug.md`,
   - воркфлоу → `WIKI/workflows/wf_NN_slug.md`,
   - кейс → `WIKI/cases/case_NN_slug.md`.
   ID берётся из имени файла. Не пиши `id` руками — он всё равно перезаписывается путём.
3. **Пересобери и проверь**:
   ```powershell
   python "C:\BLENDER ai\WIKI\scripts\run_all.py"
   ```
   Зелёный `PIPELINE GREEN` — статья попала в БД, сайт, поиск и экспорт.

## Требования к содержанию

- **Код должен запускаться.** `import bpy`, функция, возвращает `dict`, работает в чистой сцене.
  Без `os.system`, `subprocess`, записи вне `//`.
- **Имена инструментов — в бэктиках.** `execute_blender_code`, `set_material`, `get_scene_info`…
  По ним строится индекс `mcp_tools`; голое упоминание без бэктиков в индекс не попадёт.
- **Ссылки — на существующие файлы** в пределах `WIKI/`. Относительные: `./02_uv.md`,
  `../setups/setup_05_render_farm.md`. Битая ссылка валит гейт.
- **Заголовки — с эмодзи-маркерами** (`## 🎯 ЦЕЛЬ`, `## 🔧 MCP:`, `## 🔗 СВЯЗИ`): по ним
  работает навигация и рендер статей.
- **Теги** — латиницей, без `#` внутри frontmatter, без hex-цветов и чисел (они фильтруются).
- **Честность важнее объёма.** Незаконченная статья помечается `status: stub` во frontmatter,
  а не дописывается «для габарита». Читатель видит маркировку — это лучше пустых строк.

## Переводы

Файл перевода — полная копия по пути `WIKI/multilang/{lang}/{category}/{тое же имя}.md`.
ID станет `{stem}__{lang}`. Обязательно во frontmatter:

```yaml
lang: es
orig_lang: ru
translation: human     # human — переведено человеком; template — сгенерировано
```

Инвариант: **у каждого перевода обязан существовать оригинал** `WIKI/{category}/{файл}.md`
(`validate.py` §11). При переименовании оригинала зеркала надо переименовать или удалить —
иначе появятся «сироты», которые попадут в БД как отдельные статьи (так уже случилось с P01).

Перевод всего корпуса — вне объёма (`../SDD/SPEC.md` §3), но новые статьи сначала
публикуются по-русски.

## Чего не делать

- Не править руками `WIKI/db/*`, `WIKI/site/data/*`, `WIKI/export_*` — они перезаписываются сборкой.
- Не добавлять поля во frontmatter, которые никто не читает: не попадут в БД (см. `../SDD/SCHEMA.md` §6).
- Не запускать шаги пайплайна в произвольном порядке: сайт может отдать устаревшие чанки.
- Не чинить массовые проблемы вручную — `fix_links.py`, `mark_stubs.py` идемпотентны и сделают это сами.

## Если что-то сломалось

`run_all.py` печатает имя упавшего шага. Дальше:

| Симптом | Причина | Что делать |
|---------|---------|-----------|
| `build_database failed` | сломан YAML во frontmatter | `validate.py` покажет файл |
| `site meta.json + chunks out of sync` | сайт пересобран без БД | `run_all.py` без `--step` |
| `orphan translations` | переименовали оригинал | переименовать/удалить зеркала |
| `SPEC entry count mismatch` | изменился объём корпуса | обновить `SDD/SPEC.md` §2 |
| `PIPELINE GREEN`, но статьи нет | имя файла не по шаблону | сверить ID в `WIKI/INDEX.md` |
